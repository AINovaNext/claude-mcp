Meet Claude

Claude is Anthropic's AI assistant — a large language model designed to be helpful, harmless, and honest. Think of it as a very capable reasoning engine that you can talk to.

What is a Large Language Model?

Claude is built on a Large Language Model (LLM) — a neural network trained on vast amounts of text. It learned patterns, facts, reasoning, and language by processing billions of documents.

🧠

Trained on Text

Claude learned from books, code, websites, and more — giving it broad general knowledge across many domains.

💬

Conversational

Claude communicates naturally in a back-and-forth dialogue, maintaining context throughout the conversation.

🔒

Safety-Focused

Anthropic uses Constitutional AI and RLHF to make Claude helpful while avoiding harmful outputs.

The Model Context
Protocol

MCP is an open standard that lets Claude (and other AI models) connect to external tools, data sources, and services — safely and reliably.

The Problem MCP Solves

Claude alone is powerful but isolated. It can reason, write, and analyze — but it can't reach outside itself. Before MCP, every integration was custom, fragile, and hard to reuse.

🔌

No Standard Plug

Every team built their own bespoke bridge between Claude and their tools. Nothing was portable.

🔁

Duplicate Work

The same Jira connector, filesystem reader, or database tool was re-invented over and over.

⚠️

Security Gaps

No agreed model for permissions or sandboxing meant security was often an afterthought.

MCP's answer: A universal, open protocol — like USB-C for AI tools. Build a server once, and any MCP-compatible client (Claude, Claude Code, other LLMs) can use it.

1

Client discovers tools

When Claude connects to an MCP server, it asks "what can you do?" The server replies with a list of tools, their names, descriptions, and input schemas.

2

Claude decides when to use a tool

During a conversation, Claude autonomously decides when to call a tool. It constructs valid JSON arguments matching the tool's schema.

3

Server executes and returns results

The MCP server receives the call, runs the actual logic (e.g., query Jira), and returns the result as structured data back to Claude.

4

Claude incorporates the result

Claude reads the tool result and weaves it into its response — presenting data, summarizing, or continuing a multi-step task.

What an MCP Server Exposes

🛠️

Tools

Functions Claude can call: search_issues(), read_file(), run_query(). Each has a name, description, and JSON schema.

📄

Resources

Static or dynamic data Claude can read: documentation pages, file contents, configuration — like a read-only filesystem.

💡

Prompts

Pre-built prompt templates the server offers — reusable instructions for common workflows users can trigger.

When you asked "Show all tickets in SCIOPERATIONS assigned to me", here is exactly what happened:

Claude Code + MCP

Claude Code is the CLI version of Claude. It runs in your terminal and ships with built-in MCP support. You configure servers in a JSON file:

// ~/.claude/settings.json { "mcpServers": { "jira": { "command": "npx", "args": ["-y", "@sap/mcp-jira"], "env": { "JIRA_URL": "https://jira.tools.sap", "JIRA_TOKEN": "your-token-here" } }, "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/you/projects"] } } }
That's it. Claude Code starts the servers as child processes, discovers their tools automatically, and makes them available in every conversation — no further configuration needed.

Building Your Own MCP Server

You can write an MCP server in Python or TypeScript in under 50 lines:

from mcp.server.fastmcp import FastMCP app = FastMCP("my-tools") @app.tool() def get_weather(city: str) -> str: """Get current weather for a city.""" # call your weather API here return f"Weather in {city}: 22°C, sunny" if __name__ == "__main__": app.run()

Claude will automatically discover get_weather, read the docstring as the description, and call it with the right argument when you ask about weather.
